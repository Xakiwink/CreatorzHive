# `backend/compat/` — OOP Compatibility Bridge

## 1. Folder Purpose

Auto-generated (and now manually maintained) bridge files that expose OOP repository and service methods as global PHP functions. Enables procedural route handlers and legacy code to call the OOP layer without knowing about DI or class names.

## 2. Files Overview

| File | Bridges To | Number of Functions |
|------|-----------|-------------------|
| `models.php` | 14 `src/Repositories/*Repository` classes | ~60+ functions |
| `services.php` | 6 `src/Services/*Service` classes | ~20+ functions |
| `auth.php` | `src/Services/AuthService` | 9 functions |

## 3. Pattern

Every function in these files follows the same pattern:

```php
function user_find_by_email(): mixed {
    return app_resolve(UserRepository::class)->findByEmail(...func_get_args());
}
```

- Uses `func_get_args()` so the bridge never needs to declare or maintain parameter signatures
- `app_resolve()` pulls the singleton from the DI container

## 4. Naming Convention

Function names mirror repository/service method names with a prefix:

| Prefix | Repository/Service |
|--------|-------------------|
| `user_` | `UserRepository` |
| `post_` | `PostRepository` |
| `deal_` | `DealRepository` |
| `auth_service_` | `AuthService` |
| `instagram_oauth_` | `InstagramOAuthService` |
| etc. | |

## 5. Origin

Generated by `scripts/oop-generate-compat.php` and `scripts/oop-generate-services-compat.php` during the OOP migration. Now maintained manually.

## 6. Improvement suggestions

- As routes are migrated to call controllers directly (OOP dispatch), compat functions can be removed
- Consider deleting compat bridge functions that are only called from within `src/` OOP code — those should use repository/service injection instead
